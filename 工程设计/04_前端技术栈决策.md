# 前端技术栈决策

日期：2026-10-17。状态：本项目首期前端选型确定；尚未安装依赖或完成兼容性实测。

2026-10-18 同步：全站使用 [深色视觉规范 v1.0](../UI设计/视觉规范v1.0（深色）.md)，复杂动画采用 [动效设计 v1.0](../UI设计/动效设计v1.0.md)。

## 1. 核心选择

| 层次 | 选型 | 项目中的用途 |
| --- | --- | --- |
| 页面框架 | React 19 + TypeScript（strict） | 公开端、后台、共用组件与类型约束 |
| 构建 | Vite，React TypeScript 模板 | 开发服务、按需加载与静态产物构建 |
| 包管理 | npm，提交 package-lock.json | 减少团队工具差异，CI 使用 npm ci |
| 路由 | React Router，Data 模式的 createBrowserRouter | 页面路由、布局、未保存表单离开拦截；不启用服务端框架模式 |
| 样式 | CSS Modules + CSS 自定义属性 | 局部样式隔离；颜色、字号、间距、圆角集中维护 |
| 数据请求 | 原生 fetch + TanStack Query | API 封装、读取状态、缓存及保存后的刷新 |
| 页面状态 | React useState / useReducer；必要时 Context | 气泡、观看状态、表单、认证上下文；首期不另加全局状态库 |
| 三维地球 | Three.js + React Three Fiber 9 | 球体、地理点位、相机与选中反馈 |
| 复杂动画 | GSAP + @gsap/react；GSAP Flip | 镜头与 DOM 时间轴、错峰入场、封面连续转场、生命周期清理 |
| 开发 Mock | MSW | 按同一 HTTP 契约模拟后端，页面无需切换另一套数据逻辑 |
| 测试 | Vitest + React Testing Library；Playwright | 关键状态与组件测试；完整流程与代表视口检查 |
| 代码检查 | ESLint + TypeScript 检查 | 在构建前发现代码与类型问题 |
| 部署 | 静态构建产物 + 现有服务器 HTTP 服务 | 前端无需常驻 Node 服务；API 与渲染服务独立 |

React 19 与 Fiber 9 的主版本配对来自官方说明，不能任意跨主版本组合。其余依赖的确切版本在初始化时依据 peerDependencies、运行环境和构建结果锁定，不把本次选型当作“最新版已验证”。

## 2. 为什么选择这套

本项目已有独立业务后端、页面数量有限、核心为交互式地球和模型观看。采用客户端单页应用即可开始交付；目前没有提出服务端页面渲染或搜索引擎收录指标，因此暂不引入 Next.js 或另一套全栈框架。如果后续提出独立作品页 SEO 或分享抓取要求，再评估预渲染及元信息服务。

选择 React 的项目判断是统一页面与 Three.js 场景的组件管理。Vue 也能实现这些功能，本次不并行维护两种框架。React 不要求后端使用 JavaScript，现有后端成员可以继续使用自己的服务端技术。

视觉已定为深色空间展厅，采用 CSS Modules 与设计变量直接落实深色 v1.0。页面底 #080D12、主面板 #121D26、冷青强调 #54C8C1、冷银角标 #C6E2E6；公开端与后台共用。首期不引入完整后台 UI 主题，也不同时叠加 Tailwind 和另一套 CSS 体系。按钮、字段、反馈提示按真实复用需求提取；复杂可访问组件出现时单独评估现成实现。

表单起步使用 React 状态与明确的字段校验函数，草稿和发布分开校验。后端仍负责最终校验；暂不为少量表单加入额外表单框架。短反馈使用 CSS，复杂时间轴使用 GSAP + @gsap/react，Flip 处理选定的共享封面转场；首页开场、点位联动和详情转场在页面骨架阶段制作。三维相机操作与动画补间须明确接管关系。

## 3. 三维技术的确定范围

首页地球确定由 Three.js + Fiber 实现。首期约十个模型按标准城市合并点位，城市中心由城市字典提供，实际点位数不等于模型数。不包含街道导航、真实地形测量、倾斜摄影或 3D Tiles 流式场景。纹理、地理边界、城市字典与来源许可单独确认，生成参考图不能作为正式地图资产。

后台使用标准“省份＋城市”选择，城市选填，首期不引入选点地图 SDK、地址地理编码或建筑经纬度输入。城市中心由后端统一提供，作品通过 cityId 关联；未选城市不阻止发布。省市选项接口和城市聚合接口按契约评审。

模型观看器与首页地球分开，离开页面释放对应资源，不因首页使用 Three.js 就自动下载作品模型。

| 观看内容 | 决策 |
| --- | --- |
| 客户端 GLB 验证 | 使用 Three.js GLTFLoader，在独立 viewer 模块内验证 |
| 客户端高斯 PLY 验证 | Spark 为首选验证候选；实际文件通过兼容与性能验证后才纳入正式依赖 |
| 远程模型观看 | 按后端实际协议接收画面与发送控制，不由 Fiber 替代视频传输 |

Spark 官方说明支持 Three.js、WebGL2 及多种高斯格式，包括 PLY。这只是具备试验条件，不能证明当前约百万高斯的丘陵模型已在手机上达标。普通 PLY 网格／点云加载器不能直接等同于高斯渲染器。

首期优先验证客户端路线的可行性，以减少对过渡工作站的依赖；这是验证顺序，不是未经实测改变已规划的交付模式。若不达标，按原计划验证远程路径，页面技术栈保持不变。

## 4. 数据与资源约束

- API 调用集中在 api；TanStack Query 只管理服务端数据，不存模型对象、视频流或逐帧相机状态。
- 首期读取请求先关闭自动重试；登录、上传、发布、预览申请等写操作不得因库默认行为重发。预览只能由用户显式启动／重试。AI 消息发送由外部完整组件管理，主站不增加重复请求层。
- 保存／发布／下架后使相应作品详情、目录和地球城市数据缓存失效；城市变更／清空时同时刷新原城市与新城市模型列表。模型文件不放进普通 JSON 缓存。
- fetch 负责常规 JSON；上传协议需要字节进度时单独用 XMLHttpRequest 或后端指定上传实现，不能把 fetch 默认当作现成上传进度方案。
- MSW 只在开发／测试启用；生产失败不得回退假数据。真实 HTTP 路径与模拟路径共用 API 层。
- 地球、观看器与后台页面按路由或功能懒加载；模型按“开始预览”加载。大模型不打进前端构建产物。
- 认证最终由后端协议确定；不把密钥或服务器口令放入 Vite 环境变量。前端环境变量视为可公开内容。

## 5. 初始化时的版本与验证步骤

1. 检查本机及 CI 的 Node/npm；根据所选 Vite 的 engines 固定受支持 Node LTS 版本，记录到运行说明及版本文件。
2. 使用 React TypeScript 模板；锁定 React 19 / Fiber 9，核对 Three.js 与拟用渲染依赖的 peerDependencies。
3. 提交唯一 npm 锁文件；安装失败时解决冲突，不用强制忽略依赖约束作为正常流程。
4. 验证类型检查、lint、生产构建、路由刷新与最小地球场景；之后再加载真实模型做性能验证。
5. 部署配置为页面路径回退入口 HTML；API 路径和丢失的模型资源应返回真实错误，不能被页面回退吞掉。

本轮只落实选型文档；尚无 package.json、锁文件或测试通过记录。精确版本在安装与构建验证后记录，不伪造锁文件。

- [Spark](https://sparkjs.dev/docs/overview)：WebGL2 高斯渲染及 PLY 格式支持。
