# 分阶段编码提示词 · 建筑模型展厅

编写：2026-10-18。用途：交给新的编码对话，按顺序完成首期前端，并与后端、渲染和 AI 负责人联调。本文件只提供执行提示词，不表示任何代码、接口、测试或部署已经完成。

## 一、先看使用方法

### 1. 每次具体怎么发

1. 将完整项目目录放到编码工具可读取的工作区；只上传本文件不够。第一轮发送「通用约束」和「P00」。
2. P00 完成后，发送 P01；以后一次发送一个阶段代码块。不要把整本提示词一次发出去要求全部做完。
3. 同一对话继续时发送对应阶段即可；换新对话时，先发送「新对话接续提示词」，再发送本次阶段。让它读取真实代码和开发记录，不只依赖聊天摘要。
4. 每阶段的验收条件满足后再进入下一阶段；依赖未交付时，先做不受影响的步骤，把缺口记下来，不能用 Mock 冒充真实完成。
5. 涉及页面的阶段，要求实际查看相应参考 PNG，而不是只读图片文件名。看不到图片时说明限制，不宣称视觉一致。

最简单的起步方式：现在先复制「通用约束＋P00」到新对话；收到只读检查结果后再发 P01。R00 若缺实际设备或渲染服务，记录未就绪后继续 P04 等页面工作，不等待所有外部条件齐备。

本文代码块中的文件路径均相对项目根目录；项目移动后以实际根目录为准，不绑定原电脑的绝对路径。文档链接相对本文件所在目录。

### 2. 哪些资料需要一起提供

- 根目录 `README.md`、`项目搭建计划.md` 与 `工程设计/` 全部设计文件。
- `UI设计/视觉规范v1.0（深色）.md`、`UI设计/动效设计v1.0.md`、当前九张 PNG 与 `索引与逐页自查.md`。
- 若已有代码：`frontend/` 源码、依赖清单和锁文件、配置、测试及开发记录；不需要携带 `node_modules/`、构建产物和真实密钥。
- 渲染实测时再确保三件真实模型能从本地读取。不得为普通页面开发把大模型复制进公开目录、打进构建包或上传给外部服务。
- 联调阶段由负责人提供测试地址、测试账号和具体协议；通过适当的私密渠道交付敏感信息，不粘贴进本文件或提交仓库。

### 3. 依据和冲突处理

产品规则看 [确认记录](06_已确认事项与里程碑.md) 和 [城市规则](05_城市归属与地球聚合.md)；结构看 [模块设计](01_工程结构与模块设计.md)；技术看 [技术栈](04_前端技术栈决策.md)；接口看 [契约草案](02_接口契约草案.md)；验收看 [验收计划](03_开发与验收计划.md)。视觉与动画分别以当前深色规范、动效设计为准，PNG 只表达构图与氛围。

旧版归档和生成底稿不是实现依据。同日文档若有未解决冲突，先列出冲突并询问，不自行改产品决策；历史“必须申请 GPU 会话”等描述受最终渲染选路约束。API v0.2 仍未获双方确认，可以据其做标记为提案的 Mock，不能据其认定真实服务已经存在。

### 5. 每阶段的统一交付门槛

- 涉及代码修改的阶段，至少运行本阶段相关测试、类型检查、lint 与生产构建；具体命令以真实 `package.json` 为准，未执行的项目写明原因。P00 和 X05 为只读阶段，不要求安装、构建或写开发记录；纯文档评审检查其文档与契约即可。
- 页面阶段实际打开页面，检查正常、空、失败路径及代表视口；截图不能代替交互、手机手势和真实性能验证。
- 新增测试要能检验业务结果，不只检查一个 DOM 节点存在；禁止为通过检查而删测试、放宽断言、关闭 strict 或忽略依赖冲突。
- 只修复本阶段引入或直接阻断本阶段的问题；已有无关故障记录下来，不顺便重构。
- 更新 `工程设计/开发执行记录.md`，记录改动、命令与结果、浏览器检查证据、依赖状态、已知问题、下一步。本记录从 P01 创建；本轮提示词编写不提前填写实现结果。
- 阶段状态区分“未开始／进行中／Mock 已验证／真实联调通过／实机通过／受阻”。不能把“完成页面”写成“产品全部完成”。

## 二、通用约束：新对话首次发送

使用时机：每个新编码对话开始时，与 P00 或接续提示词一起发送。同一对话无需每轮重复粘贴。

```text
你正在实现“建筑模型展厅”。先识别实际项目根目录，遵守可用的 AGENTS.md 和项目设计。本次只做我指定编号的阶段，不自动跨阶段，不擅自推送、部署、发送消息、创建外部任务或上传模型。

先读根 README 和本阶段列出的资料及相关现有代码。说明必要假设，给出简短实施与验证安排后执行。确定的细节无需重复问我；会改变产品范围、认证、安全、真实协议或数据的歧义先询问。不能读取必要文件或图片时如实说明。

固定边界：
1. React 19、TypeScript strict、Vite、npm、React Router Data 模式、CSS Modules＋CSS变量、fetch＋TanStack Query、Three.js＋Fiber 9、GSAP＋@gsap/react＋Flip、MSW，测试用 Vitest/RTL 和 Playwright。按初始化时官方兼容说明锁定具体版本，不强制绕过 peerDependencies，不改用 Next/Vue/Tailwind 或完整后台主题。
2. 全站深色 v1.0。正常模式保留首页空间入场、城市点位／镜头联动、封面到详情连续转场；每页同步手机适配。减少动态偏好独立处理，不能把正常模式统一简化为淡入淡出。
3. 城市选填；标准省市字典和稳定 cityId；同城已发布作品一个点位，城市气泡列出模型。无城市可发布，只进入公开目录与详情，不创建未知城市点，不出现地图选点或建筑经纬度字段。
4. 首期10件模型；演示不足可明确占位。纯文字介绍与建模说明保留换行，不渲染HTML/Markdown；不加作者／日期、搜索、分类、分页、下载、注册找回、统计或真正评论点赞功能。

6. 详情先封面，用户点击开始／手动重试才启动完整模型加载或创建会话。繁忙、断线不自动重试、不排队；放大恢复保持同一实例和视角，结束／切换／卸载清理资源。
7. AI由他人交付完整组件，主站只引入、配置、挂载和卸载；仅公开端，未交付隐藏入口，不自建聊天UI或假回答。供应商密钥、真实口令不进入前端或文档。
8. API仍有草案项。开发Mock必须显式启用并标识，生产失败不得回退Mock；不把模拟上传、预览或登录写成真实完成。服务端负责最终权限、发布和资源校验。
9. 最小范围修改，不删除原始资料、模型或用户修改，不进行无关重构。不要预建通用插件平台、事件总线、多渲染调度器或第二套后端。

涉及代码修改时，完成后运行相关检查与页面走查，记录实际命令、结果及未验证项，更新“工程设计/开发执行记录.md”。P00和X05只读，不写记录或安装依赖；纯文档任务只做相应校验。最终简要列出改动文件、可查看地址、通过项、阻塞项和下一建议阶段；没有运行的检查不能写通过。
```

## 三、按编码顺序执行的提示词

### P00｜只读开工检查

什么时候用：新项目第一次开工。此段不授权初始化或改代码。

```text
执行P00，只读检查，不写代码、不安装依赖。

阅读README、工程设计01–06、当前深色视觉规范、动效设计和最新九图索引；核对实际文件和现有代码。项目搭建计划按相关条目核对，历史原型不覆盖最新城市、AI和视觉决定。

给我一份开工基线：已有文件／代码、已确认规则、尚未确认的接口与外部依赖、可先做与受阻模块、下一个可执行阶段。区分“可做页面Mock”和“可做真实集成”。核对当前参考图不是旧版归档。

检查frontend是否已存在、是否有用户改动、可用Node/npm与仓库状态。只读命令若环境不支持就报告，不安装任何东西。已有工程不得在后续被模板覆盖。

通过条件：无未解决的产品规则冲突，能说明P01具体落在哪里；真实认证、上传、渲染、AI的缺口有明确清单。不要求我重新回答已经确认的产品问题。
```

### P01｜初始化工程、路由和检查工具

什么时候用：P00 检查完毕后。第一次真正写工程代码。

```text
执行P01，只完成最小可运行前端基础。
依据：工程设计01、04和README；先检查现状，有工程则补齐，不重新生成覆盖。

在frontend独立工程中落实React19＋TS strict＋Vite＋npm与唯一锁文件，createBrowserRouter的Data模式。核对所选Vite的Node engines和各依赖兼容要求，记录支持的运行版本。按真实需要安装当前阶段依赖，后续三维/动画依赖也必须遵守既定选型。

建立公开布局、后台布局及01文档列出的全部路由、404和路由错误展示，页面可先用明确开发占位。不实现业务表单或假认证。公开和后台模块可懒加载；直接刷新作品与管理路径应能进入前端路由。

建立类型检查、lint、build、单元测试和最小Playwright配置及可复现脚本，提供开发／测试运行说明和.env.example。生产默认不启用Mock，环境变量仅放公开配置；大模型不进入public、源码导入或构建产物。只忽略依赖、产物、本地密钥等明确项目。

创建工程设计/开发执行记录.md：每阶段状态、实际检查证据、外部依赖清单和下一步，不预填通过。必要时记录当前既有问题作为基线。

验收：安装依赖无强制忽略冲突；类型/lint/build通过；至少首页、作品详情、后台编辑路径与404可直接访问和刷新；基本路由冒烟实际运行。不要把开发服务器的路由回退误写成正式服务器已配置完成。
```

### P02｜深色设计变量、基础组件与双端布局

什么时候用：工程能启动后，正式组合页面之前。

```text
执行P02，建立足够支撑首期页面的视觉基础，不制作整套通用组件库。
阅读UI设计/视觉规范v1.0（深色）.md全文，结合最新图集看首页、目录、详情和后台布局。

用CSS变量集中颜色、字号、间距、圆角、层级和动效时长，CSS Modules组织局部样式。核心表面为#080D12、#121D26、#0D161E、图像承托#20272B；主文字#EBF2F5、次文字#A8BAC4、冷青#54C8C1、冷银#C6E2E6，按钮深色字。其余值按规范，不从生成图吸色推算。

实现真正复用的按钮、带标签的输入/选择/文本域、字段错误、状态提示、作品卡片基础、公开导航、管理布局、跳到主要内容与基础焦点样式。只为当前页面需要抽组件，避免为单次使用写大量配置。

按规范落实手机实色导航、后台与长文实色、图像中性底及玻璃预算规则。原生控件能满足时优先使用；不靠不可见命中区以外的视觉技巧掩盖实际可用性问题。字体未到时使用明确回退，并记录待替换及许可，不能声称已经安装正式字体。

验收：320/390/768/1440 CSS像素下导航和必要控件可用；键盘focus、禁用、错误、等待状态可辨识，无横向溢出。进行实际页面预览与截图，不把组件演示页新增为正式产品模块。
```

### P03｜类型、API 层、缓存键和开发 Mock

什么时候用：写业务页面前。协议未经确认也可执行，但所有提案和样例要标明。

```text
执行P03，按工程设计02、05、06建立业务数据边界和MSW，不实现真实后端。

定义PublicWork、AdminWork、City、Province、UploadAsset和统一错误等实际所需类型，区分公开/管理数据及glb/gaussian-ply。cityId省略表示不修改，null表示清空；作品不包含建筑经纬度。发布排序由契约保证发布时间降序、id稳定排序，公开端不为排序增加作者/日期展示。

集中封装fetch请求、认证配置入口、错误转换、AbortSignal与TanStack Query键。请求先关闭自动重试；写操作不自动重发，预览启动不能挂在会自动执行的页面读取中。不要把模型对象、逐帧相机、视频流放进Query缓存。

MSW只在显式开发/测试模式启用，与真实HTTP共用请求层。提供明确10件演示目录：已知三件是开发样例，其余标占位；另设草稿/下架等测试夹具，不虚构正式资料。相同数据源派生公开列表、城市聚合和管理数据，变更后保持一致。

提供可控的正常、空、读取失败、404、401、422、409等场景；城市覆盖同城多件、无城市、只有无城市、中心缺失、字典失败和无效id。Mock认证与资源状态只能用于演示，不能当安全方案。定义测试间重置方法，演示刷新持久化是否存在写清楚。

验收：类型严格；Mock禁用时确实走真实HTTP且失败不回退假数据；草稿/下架不公开、无城市已发布留在目录但不进地球；API错误与null语义有测试。上传及预览端点未确认的部分保持提案，不发明成既定协议。
```

### R00｜尽早并行：真实模型渲染验证与选路

什么时候用：P01/P03 后即可开始；有代表设备和模型时优先做。此阶段是验证，不等于正式观看器交付。

```text
执行P24，按工程设计03最终验收，不把本地通过当线上通过。

在真实交付URL复验首页/目录/详情深链、城市聚合/无城市、登录上传草稿发布下架、管理员预览、手动观看/结束/放大、AI真实问答和失败。检查HTTPS、认证持久性、资源路径/缓存、真实渲染可用性和已约定并发/设备目标。

核对10件正式作品与资料许可、无占位冒充正式资产、生产无Mock或开发场景开关。若少模型、AI未交付、真高斯未通过、容量或手机性能未达目标，列未完成与影响，请求明确验收决定，不能直接勾“全部完成”。

整理源代码、锁文件、启动/构建/测试说明、确认版接口与变更、部署/回滚/备份、渲染运行、内容资源清单、设备与联调证据、已知限制和维护负责人。测试账号敏感信息单独交接，不写明文进仓库。

最后给出：已通过的实际范围、未通过/未测项、线上地址、运行/维护入口、后续必要事项。没有线上访问权限则只完成本地交付审计并标线上未验，不能凭截图宣布正式交付。
```

## 四、遇到特定情况时再用的提示词

### X01｜新对话接续，不要重新初始化

什么时候用：任何阶段换新对话、上下文丢失或换协作者时。与通用约束及选定阶段一起发送。

```text
接续现有工程，不重新初始化。先读README、工程设计/开发执行记录.md、当前实际代码和本次阶段的依据；记录不存在则如实说明并从代码核实，不能推断全部未开始或全部完成。

核对已通过项的实际测试/文件证据、用户现有修改、Mock与真实集成状态、未解决外部依赖。用几句话说明你认定的当前进度和下一可执行阶段；与记录不一致先报告，不覆盖已有成果。随后只执行我指定的阶段，不重做已验证工作，不自动跨阶段。
```

### X02｜发现 Bug：复现、最小修复、回归

什么时候用：开发或验收中发现具体错误。先填入现象和复现信息，不只发送“修好所有 bug”。

```text
修复以下具体Bug，不扩展功能，不重做视觉或架构。
现象：[填写]
页面/作品/环境：[填写URL、浏览器和Mock/真实]
复现步骤：[填写]
预期：[填写]
实际与日志/截图：[填写并脱敏]

先复现并定位根因，检查相关调用与状态；能自动化时先加会失败的回归测试，再做最小修复。检查重复点击、取消/迟到、权限/城市空值等与本Bug直接相关的边界，不做无关重构。

重跑复现步骤、相关测试、类型/lint/build。报告根因、改动、证据和仍未验证处。不能复现时说明已做检查及缺的最少信息，不猜改代码；若问题来自后端或外部组件，给可核实请求/版本证据，不用前端假成功遮盖。
```

### X03｜局部视觉或动效调整

什么时候用：已有页面后，只想改某一块的构图、尺寸或节奏；不重新生成整站。

```text
仅调整[页面/区域]的[具体问题]，对照[当前参考图/规范章节/已附运行录屏]。
保留已确认深色主题、功能、城市规则、路由、API和观看生命周期，不修改其他页面或重做组件体系。

先指出偏差及最小修改范围；调布局时同步检查320/390/768/1440与长内容，调动画时检查中断/快切/返回/resize/减少动态。正常模式保留核心复杂动画，不用整体删动画解决局部卡顿。截图仅验布局，动效提供运行证据。

修改后检查相关回归、类型/lint/build，列实际变化和未测项；涉及新增业务控件、改变交互模型或删减核心编排时先问我。
```

### X04｜联调被外部依赖阻塞

什么时候用：缺上传协议、测试账号、渲染服务或 AI 组件，不应继续猜实现时。

```text
整理当前阻塞，不伪造协议、不制作假成功来宣称真实接入。
针对[模块]，列已具备内容、缺的具体交付、需要谁确认、收到什么样例/文件/测试结果即可继续，以及受影响的阶段。

对不受影响的本项目工作给出下一可执行项；不要自行联系协作者或修改他们的系统。开发Mock可保留但标识清楚，生产不得回退。更新开发执行记录，明确哪些是已实现、仅模拟、未联调、未实机验证。
```

### X05｜以后切换渲染方案：先评估再迁移

什么时候用：工作站改服务器或远程改客户端时。不是当前首期自动执行的任务。

```text
先评估将[当前模式]迁移到[目标模式]，本次仅只读分析与迁移方案，不立即改代码或下线现有服务。

基于实际viewer边界、资源版本、权限、生命周期、部署和实测记录，列能复用与必须重做项。远程改客户端需重新处理模型下载/解析/相机/设备性能/资源释放/旧资源访问；客户端改远程需会话/媒体/控制/回收/容量；同协议工作站换服务器也要验证网络、编码、存储和容量。

无GPU服务器的CPU能力必须真实资源实测，不预设可实时交付。提出验证门槛、迁移步骤、回归清单和回滚方式，指出对下架/替换/已建立观看的影响。团队确认模式与协议并明确授权实施后，再编写只覆盖选定方案的迁移执行任务。
```

本手册依据当前项目文件逐模块编写。通用的“目标、必要上下文、边界、验证结果”组织方式参考 [OpenAI 官方提示词指南](https://learn.chatgpt.com/docs/prompting)；具体阶段拆分、先后关系与验收门槛为本项目的工程安排，不是官方要求。提示词能帮助控制范围与暴露风险，不能保证零 Bug，仍需真实测试、协作者协议与人工验收。
