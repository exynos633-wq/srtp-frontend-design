### 需要修改

#### [中] `uint16` 等颜色类型仍会被渲染成白色

相关代码：

- `frontend/src/viewer/parseMeshPly.ts:322-325`：只校验 `red/green/blue` 是标量，允许 `uchar`、`ushort`、`uint`、`float` 等任意标量。
- `frontend/src/viewer/parseMeshPly.ts:448-453`：只对 `uint8` 除以 255，其余类型除以 1。

```ts
return property.type === 'uint8' ? 255 : 1
```

如果 PLY 使用 `ushort red/green/blue`（0–65535），颜色值都会大于 1，随后被 `Math.min(1, …)` 裁成白色。建议二选一：

1. 只接受 `uint8` / `float32` / `float64`，其他颜色类型明确报 `PLY_FIELDS`；
2. 或按类型归一化：

```ts
const scalarColorDivisor: Partial<Record<ScalarType, number>> = {
  uint8: 255,
  uint16: 65_535,
  float32: 1,
  float64: 1,
}
```

无论选择哪种，补一个 `ushort` 颜色测试。

#### [低] 行数上限建议先比较再累加

相关代码：`frontend/src/viewer/parseMeshPly.ts:178-181`。

```ts
totalRows += element.count
if (totalRows > MAX_ELEMENT_ROWS) fail(...)
```

严格说这不是可实际利用的绕过：`element.count` 已限制为安全整数，表头最多 512 KiB，累加结果仍会大于上限；但它会先产生超出安全整数精度的中间值。建议改为：

```ts
if (element.count > MAX_ELEMENT_ROWS - totalRows) fail(...)
totalRows += element.count
```

这样语义更直接，也避免精度/溢出疑虑。

#### [低] `fetchQuery` 没有取消信号

相关代码：`frontend/src/pages/admin/WorkPreviewPage.tsx:155-159`。

`fetchQuery` 没有传 `signal`。路由离开或组件卸载后，预览配置请求仍会继续；React Query 会缓存结果且不会直接 setState，但这是可避免的请求浪费。可以给 `resolveAdminWorkModelSource` 增加可选 `signal`，或接受这一低风险行为并注明。
