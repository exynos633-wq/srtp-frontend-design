# 城市归属与地球聚合

日期：2026-10-18。状态：产品规则已由用户确认，以下接口与数据结构为前后端评审草案；尚未实现。

## 1. 已确认的行为

- 上传／编辑只选择模型所在城市，城市选填；不录入建筑经纬度、不提供地图选点。
- 使用标准“省份 → 城市”选择，保存稳定城市编号，不用自由文本作为分组键。直辖市也从省级选项进入对应城市，避免“北京／北京市”产生两个点位。
- 同一城市的已发布模型合并为一个地球点位，点位位于城市中心，表示城市归属，不表示建筑的精确位置。
- 点位气泡显示城市名称和该城市的模型列表；点击具体模型进入共用详情页。一座城市只有一个模型时也沿用同样结构。
- 未选城市的模型可保存、发布，在全部模型目录和详情中正常浏览，不进入任何地球城市卡片，不创建“未知城市”或默认坐标点位。
- 城市不是发布条件。发布仍要求模型资源、名称、封面、建筑介绍；建模说明和城市选填。

现有导航“全部作品”即用户所说的“全部模型”，继续使用现有路由 `/works`，此项需求不引入第二个目录。

## 2. 城市选择与空值

表单标记“所在城市（选填）”，辅助说明“填写后可从地球城市卡片发现；不填仍可发布并在全部作品中查看”。省份只用于筛选城市；只选省份但未选城市，作品的 cityId 仍为 null，不算已设置位置。

切换省份时清除之前不属于该省份的城市，清空城市使用明确的清除操作。保存已有城市前若字典读取失败，保留已有选择；不能把加载失败当作用户主动清空。

目录、详情和后台未填时统一显示“未设置城市”，属于正常内容状态，不使用错误／待完善警示。不能把它写成发布失败。城市字典未知或无效编号由服务端拒绝并返回字段错误，允许用户重新选择或主动清空。

已确认首期仅国内，使用标准省市字典；不实现海外城市选择。字典来源、版本、国内地区覆盖及城市中心坐标由后端落实，不把无可核实城市的模型随意归入某城。

## 3. 地球与卡片

地球仅展示“至少有一件已发布模型且具有有效中心坐标”的城市。全部作品则展示所有已发布模型，两者数量可以不同；按城市数量画点，不按模型数量画点。

气泡仍靠近点位出现，桌面悬停、手机点击、键盘聚焦均可进入；同一时间最多打开一个城市气泡。城市标题与每个模型入口分开，列表项显示封面、模型名称和进入详情的操作，整项只有一个链接目标。已确认模型顺序与全部作品一致，按发布时间降序、id 稳定排序，一次展示全部，不分页分类。

列表内容较多时气泡内部纵向滚动，标题和关闭操作可达；键盘能遍历每个模型入口，手机能滚动列表而不误拖地球。保持已有边缘避让和深色玻璃规则，不自动把城市卡片变成底部抽屉。

城市列表读取失败可就近重试，不因读取卡片创建模型预览会话。全部模型已发布但均未设置城市时，地球无点位，显示“暂无可从地球探索的城市，请前往全部作品查看”，不能显示“暂无作品”。

修改已发布模型城市并保存后，刷新作品详情、全部作品、原城市和新城市的地球数据。清空城市移出原城市列表；原城市不再有已发布模型时移除点位，若气泡正在打开则关闭并合理恢复焦点。下架作品同样更新城市列表及点位；已建立的模型预览仍遵守原会话规则。

城市中心数据缺失属于城市数据配置问题，不是上传者缺少经纬度；不伪造坐标，不阻止其他必填项完整的作品发布，后台显示该作品暂不能从地球发现的真实原因。

## 4. 数据和接口边界

作品写入城市字段：`cityId: string | null`。PATCH 省略 cityId 表示不修改，显式 null 表示清空。省份与城市名称来自同一字典，服务器不接受互相矛盾的自由名称。

作品读取字段：`city: {id, name, province: {id, name}} | null`；后台另返回可编辑的 cityId。作品不再保存或要求建筑级经纬度。

城市中心独立维护：`cityId → center: {longitude, latitude}`，坐标体系建议 WGS84。地球仍需要这些内部定位数据，管理员只选城市；鼠标／触摸输入坐标不受本变更影响。

接口提案详见 [接口契约](02_接口契约草案.md)：省市字典、地球城市列表、某城市已发布模型列表。作品发布状态由服务端统一过滤，草稿和下架模型不能出现在公开城市气泡中。接口路径和数据来源仍需后端确认。

## 5. 验收与素材影响

应覆盖：同城多个模型只有一个点位；不同城市分别成点；未选城市发布成功且只进目录；仅有无城市模型时地球提示正确；无效城市编号被拒；城市修改／清空、下架最后一个模型后点位更新；城市卡片多项滚动与键盘可达；城市字典失败不清空已有值。

深色风格与复杂动画继续执行。点位／镜头联动目标改为城市；卡片内点击某件模型后，只对这件模型的封面执行进入详情的连续转场。
