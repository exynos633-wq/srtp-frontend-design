# 工程结构与模块设计

状态：设计初稿。前端已选 React + TypeScript + Vite，详见 [技术栈决策](04_前端技术栈决策.md)；精确依赖版本初始化时验证锁定，本文件不预设后端语言。

## 1. 页面与路由草案

| 路由 | 页面 | 数据与主要行为 |
| --- | --- | --- |
| `/` | 地球探索 | 已发布模型按城市合并点位、一个城市气泡内列出模型、进入具体详情 |
| `/works` | 全部作品 | 全部已发布模型的封面、名称、城市或“未设置城市”；包含未选城市的模型 |
| `/works/:id` | 作品详情 | 信息与封面、手动预览、介绍、评论与点赞预留 |
| `/admin/login` | 管理员登录 | 登录成功返回原管理页，否则进管理列表 |
| `/admin/works` | 作品管理 | 草稿、已发布、已下架作品及允许的操作 |
| `/admin/works/new` | 新建作品 | 不完整资料可保存草稿 |
| `/admin/works/:id/edit` | 编辑作品 | 上传、修改、保存、预览、发布／下架 |
| `/admin/works/:id/preview` | 管理员预览 | 复用观看区，通过授权读取未公开作品 |
| 其他路径 | 未找到页面 | 返回首页或目录 |

路由隐藏不构成授权；管理数据、草稿读取、上传和发布必须由服务端校验身份。

全部作品及城市卡片模型列表按发布时间降序、id 稳定排序，一次展示全部，首期不分页或分类。介绍与建模说明只显示纯文字并保留换行，不增加作者／日期字段。

## 2. 模块边界

页面负责组合模块；API 层负责请求和统一错误转换；样式变量负责色彩、间距、字号、圆角。页面不硬编码服务器地址，不直接处理视频连接或模型解析。

地球模块接收城市编号、城市中心与公开模型数量，选中城市后读取该城市已发布模型列表；点击具体模型时发出作品编号事件，不读取完整模型。地球和全部作品都按服务端发布规则过滤，但地球只包含有城市归属及有效中心的模型，目录包含所有已发布模型。后台采用标准省市选择，城市选填，取消地图选点与建筑经纬度字段，详见 [城市规则](05_城市归属与地球聚合.md)。

观看区接收作品身份、封面与预览配置，对页面提供开始、复位、结束及状态通知。放大查看由观看区外壳负责，保持同一实例和当前视角。旋转与缩放交给实际渲染实现，不强行把本地相机操作映射成远程网络消息。

只在实际需要时增加共用组件，不预建通用插件框架、事件总线或多渲染器调度平台。全局仅保留认证等跨页必要状态，表单和气泡状态就近管理；AI 助手内部状态由交付组件负责。

## 3. UI 实现设计

实现次序：设计变量 → 按钮／输入／反馈提示 → 作品卡片／观看区外壳 → 页面组合。

先做作品目录 → 详情 → 未启动／准备中／失败的完整流程，使用真实封面检查版面；并行验证地球点位。随后实现后台。桌面和手机在每页完成时一起检查，不把手机适配推迟到最后。

布局、色彩与组件遵循 [深色视觉规范 v1.0](../UI设计/视觉规范v1.0（深色）.md)；图片仅作为方向参考。首页、目录、详情和后台共用深色设计变量。复杂动画按 [动效设计 v1.0](../UI设计/动效设计v1.0.md) 与页面骨架同步制作，优先完成首页开场、点位联动和封面到详情的动态样片。

建议起步交互（待实现验证）：

- 点位最多打开一个气泡；电脑从点位移入气泡时保持，手机点击空白或关闭按钮收起。
- 点位代表城市，气泡显示城市名和模型列表；每项一个进入详情的链接，多项时内部可滚动，不因打开气泡启动预览。
- 未设置城市的模型可发布，只在目录与详情可见；省市字典失败保留已选城市，选择省份本身不产生点位。
- 拖动地球时关闭气泡；背面点位不显示、不允许误点。重叠点位的选择方式需在真实坐标上验证。
- 详情返回保留来源页面；直接访问详情时返回作品目录。
- 未启动时不下载完整模型、不申请远程会话；按钮点击后才启动对应实现。
- 放大查看使用页内覆盖层，支持关闭及键盘退出；关闭放大层不等于结束预览。
- 表单失败保留已填内容；发布失败定位字段；已有修改离开前提醒。
- 已发布模型修改／清空城市后同步刷新原城市、新城市、目录与详情，空城市移除点位；地球无城市点时仍可前往有内容的全部作品目录。
- 手机滑动正文保持正常滚动，模型手势仅作用于观看区，具体触摸行为随渲染验证校准。

AI 助手：按负责人提供完整组件规划，assistant 模块仅保留引入、配置、挂载与卸载逻辑。已确认仅挂载公开展示区，后台及后台登录不挂载；未交付／未启用时不显示入口。消息、会话、聊天面板及内部动画由组件负责；若组件自带入口，不重复绘制按钮。主站通过公开配置适配深色主题、位置、层级与手机安全区；公开路由间不重复挂载，进入后台等离开挂载范围时按组件约定清理。实际交付形式尚待对接。

## 4. 渲染迁移边界

前一轮“换适配层即可”的描述过于简化。页面可复用不等于渲染实现可直接替换。

| 变化 | 通常能保留 | 需要重新实现或验证 |
| --- | --- | --- |
| 工作站换 GPU 服务器且协议不变 | 页面、业务接口、观看客户端 | 部署、网络、容量、模型路径、编码与运行环境 |
| 远程换客户端渲染 | 页面布局、作品信息、观看外壳及操作语义 | 模型下载与解析、相机、内存释放、加载状态、设备性能 |
| 客户端换远程渲染 | 页面和基本操作入口 | 会话、传输、输入映射、连接状态、超时和并发管理 |

两种路径共同使用：未启动、准备中、可交互、失败、结束。远程另有繁忙、断线、节点离线；本地另有资源下载失败、格式不支持、设备能力不足。不向本地预览伪造远程会话或繁忙状态。

本地资源版本和远程会话都应关联具体模型资源。远程结束需释放服务端资源；本地结束需终止未完成加载并释放渲染资源。组件卸载后到达的旧加载结果应被忽略并清理。

现有“下架后已有会话继续、等会话结束才替换”的规则适用于远程模式。本地模式不能收回已下载的数据；若切换本地，需要约定资源版本、访问地址有效期、缓存及旧资源保留策略，不能直接复用远程会话计数规则。

当前设计保留观看区边界，只实现选定路径；不为未来可能性同时开发两套渲染器。无 GPU 服务器是否能满足实时渲染目标尚无实测，不能把 CPU 方案写成可交付承诺。
