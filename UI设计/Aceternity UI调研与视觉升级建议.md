# Aceternity UI 调研与视觉升级建议

调研日期：2026-10-22。

范围：结合第一版前端代码、视觉／动效 v1.0、Aceternity 官网组件文档及公开 registry 源码，提出第二版视觉方案。本文件是研究建议，不代表已实现或已通过浏览器、设备和性能验收；本轮未运行站点做动态视觉评审。

最新方向依据：用户明确要求更有美感、高级感与吸引力，动画不用刻意低调。与该方向冲突的旧版审美限制，在下一版设计中应重新制定。现有业务流程继续作为设计基础。

## 1. 调研结论

Aceternity 有适合本项目的组件，尤其是展陈聚光、指针交互卡片、局部边缘光、玻璃导航与有空间关系的转场。建议形成“电影感建筑数字展馆”的统一方案：大尺度中文标题、真实建筑图像、深色空间背景、冷暖灯光、可感知的景深与连续转场。

正常模式可以明确地呈现光效、倾斜、视差和镜头编排。高级感的判断应包括静态构图、材质统一、作品展示质量与运动节奏，不能只按特效数量判断。

优先组合：**Spotlight New + Comet Card（或 3D Card Effect 二选一）+ Glowing Effect + Magnetic Button + 现有 GSAP 封面连续转场**。Liquid Glass 作为导航／观看控制条的增强材质，需单独验证兼容性。

## 2. 当前实现中值得优先改变的部分

以下是代码和文档检查结果，不是运行截图评价。

| 当前情况 | 对呈现的影响 | 第二版建议 |
| --- | --- | --- |
| `HomePage.tsx` 的主标题仅供屏幕阅读器使用，首页主要呈现地球 | 缺少可见的文字视觉锚点与品牌表达 | 加入大尺度标题、副文案和清晰入口，与地球形成非对称构图 |
| `tokens.css` 页面标题桌面 34px、手机 28px | 展示页标题与常规应用界面的尺度接近 | 为展示页单独增加 display 字号，不放大后台字段与所有标题 |
| 目录卡片为等尺寸网格；hover 为上移 3px、封面缩放 1.025 | 层次与交互变化较少 | 增加主次版式、封面遮罩揭示、指针倾斜与边缘光 |
| 详情桌面为左观看、右介绍面板 | 观看页带有较明显的工具布局特征 | 探索大画幅观看区与编辑式标题／介绍排版，控制面板更精致 |
| 正式字体未入库；Mock 完整作品使用同一个 `placeholder-cover.svg` | 字体与作品图像尚不足以支撑最终视觉判断 | 准备有代表性的真实封面和字体后再做最终视觉验收 |
| `Earth.tsx` 使用演示纹理与相机跟随光照 | 地球质感仍受演示资产限制 | 单独研究更好的地理纹理、明暗分区与大气层表现 |
| 已有 GSAP 镜头、目录错峰、封面 Flip、减少动态处理 | 已具备连续交互基础 | 在现有动画结构上升级，不重复搭建另一套相同转场 |

旧规范对彩色光晕、整圈高亮、导航材质、标题大小和布局有明确约束。第二版可允许展陈环境光、局部发光和更自由的版式；同时保留真实模型材质、明确状态和可读文字。

## 3. 组件候选与落点

下表“推荐程度”“使用位置”与强度均为针对本项目的设计判断。组件名称与原始能力来自官网，链接可查看官方演示。

| 组件 | 原始能力 | 本项目的使用方式 | 推荐程度 |
| --- | --- | --- | --- |
| [Spotlight New](https://ui.aceternity.com/components/spotlight-new) | 可配置的左右聚光背景 | 首页标题区与地球背后形成冷白／淡青展陈光，衬出空间纵深 | 首批 |
| [Comet Card](https://ui.aceternity.com/components/comet-card) | 随指针倾斜和平移的透视卡片 | 目录作品卡、城市气泡中的作品缩略卡；与 3D Card 二选一 | 首批，先试主目录 |
| [3D Card Effect](https://ui.aceternity.com/components/3d-card-effect) | 卡片透视及内部元素分层浮起 | 更强调封面、标题、箭头之间的景深；适合代表作品卡 | Comet 的备选 |
| [Glowing Effect](https://ui.aceternity.com/components/glowing-effect) | 适配容器、跟随交互的边缘光 | 光线沿当前作品卡片边缘流动；冷白、青色、少量暖金可试 | 首批 |
| [Magnetic Button](https://ui.aceternity.com/components/magnetic-button) | 按钮随指针漂移并弹性回位 | 首页主要入口、“开始预览”按钮；小范围吸附 | 首批 |
| [Resizable Navbar](https://ui.aceternity.com/components/resizable-navbar) | 随滚动改变宽度的导航 | 目录／详情滚动时由宽导航收拢为浮动导航；首页无需伪造滚动触发 | 第二批 |
| [Liquid Glass](https://ui.aceternity.com/components/liquid-glass) | 带边缘折射的玻璃表面 | 短导航、少量工具按钮、观看控制条；先做浏览器样片 | 第二批实验 |
| [Text Generate Effect](https://ui.aceternity.com/components/text-generate-effect) | 短文本分段淡入，可带模糊消散 | 首页中文标题按完整行／语义词组揭示；需要改分词逻辑 | 首批借鉴 |
| [Parallax Hero Images](https://ui.aceternity.com/components/parallax-hero-images) | 最多八张图像随指针按深度移动 | 目录顶部用少量现有作品封面组成空间画廊；与首页地球分开使用 | 可选增强 |
| [Hero Parallax](https://ui.aceternity.com/components/hero-parallax) | 多排作品随滚动位移、旋转和透明度变化 | 借鉴滚动编排语言，用于目录局部展示段 | 有素材后再试 |
| [Container Scroll Animation](https://ui.aceternity.com/components/container-scroll-animation) | 容器滚动时从倾斜变为正视 | 仅用于未开始预览的封面展台；实际模型交互时必须稳定正视 | 可选 |
| [Moving Border](https://ui.aceternity.com/components/moving-border) | 沿容器边缘循环移动的光 | 主入口或开始预览按钮的替代方案，与其他按钮光效二选一 | 可选 |
| [Lens](https://ui.aceternity.com/components/lens) | 局部图像放大 | 有高分辨率封面后用于静态建筑细节；避开模型拖动手势 | 素材就绪后 |
| [Compare](https://ui.aceternity.com/components/compare) | 拖动分界比较两张图像 | 未来有同视角实景／重建图时可用 | 当前缺内容，不纳入首批 |

## 4. 推荐的整站视觉方向

### 4.1 画面语言

- 底色用接近黑色的墨蓝／炭黑，表面通过亮度和材质拉开层次。
- 银白作为主要标题色，青色作为交互锚点；暖金或暖白取自建筑木材、石材与照明，形成冷暖对照。最终颜色需随真实封面校准。
- 首页展示标题桌面先试 64–88px，手机先试 36–44px；目录标题可试 48–64px。它们都是样片起点，不是既定验收尺寸。
- 中文可以试“展陈标题用现代宋体、界面和正文用黑体”，也可以继续黑体但显著拉开字重与尺度；先比较两张真实内容样稿，再定字体。
- 页面空间需要呼吸感；目录、详情的外壳不必都画成同一种满边框面板。
- 圆角区分导航、作品卡与工具按钮，不再仅用同一个小圆角表达所有材质。

### 4.2 首页：进入展馆

桌面构图建议：左侧标题与一两行介绍，右侧／偏中为大地球，背景聚光将两者组织在同一空间。城市点位仍是作品的真实入口。

标题文案草案：“从一座城，走进一座建筑。”站名仍用“建筑模型展厅”，避免擅自引入未确认的正式品牌名。

开场建议，资源就绪后约 1.3–1.7 秒完成主要编排，操作从一开始可用：

1. 展陈背景与光线先建立空间。
2. 地球完成镜头推进，与标题的逐行揭示重叠。
3. 城市点位错峰到位，主入口完成一次短光线扫过。
4. 进入可探索状态，点击点位时镜头、点位确认、连接线和城市作品卡连续衔接。

聚光图层不拦截拖动、缩放和点击；移动端标题与地球上下重排，保留清楚的视觉主次。

这里的 Spotlight 是 DOM 背景装饰，不会真正照亮 Three.js 球体。地球明暗、大气与纹理需在 `Earth.tsx` 中独立改进，才能形成一致光向。

### 4.3 目录：可浏览的建筑画廊

顶部用大标题建立目录身份；有足够真实封面时，可加入一个简短的多层图像展示段。

作品主体尝试有主次的编辑式网格：第一件放大，其余沿明确阅读顺序排布。视觉放大仅来自当前排序，不虚构“精选”“最受欢迎”等业务标记，也不为了填满首屏重复作品。

卡片交互建议：指针进入 → 封面与卡面产生景深 → 边缘光随指针移动 → 名称／入口箭头轻微推进。初步试验倾斜约 4–7°，视觉位移约 4–10px，离开后用弹性回正。触屏通过按压反馈与入场揭示保留品质感。

目录已经有视口揭示与封面进入详情转场，升级时应增强封面遮罩与内部层次，并保留浏览器返回位置和焦点恢复。

### 4.4 详情：让作品成为画面中心

探索大画幅封面／观看区、醒目的建筑名称与更从容的介绍排版。可以让标题和城市先形成作品身份，再进入观看与阅读；手机顺序仍以观看操作和内容可读为依据。

开始预览前，封面可以有展台式入场、表面反光和可感知的按钮反馈；开始预览后，观看区和控制条保持稳定，鼠标与触摸直接操纵模型。光效主要放在外壳和背景。

既有封面 Flip 继续承担“目录卡片 → 详情”的连续性，避免又叠一遍整页旋转转场。介绍以区块／完整段落入场，长文无需逐字等待。

### 4.5 后台

后台可跟随新的字体、色彩、间距与按钮材质获得统一感。本轮视觉重心在公开展示页；后台列表、输入框和保存反馈按操作效率设计，不需要套用作品卡的倾斜机制。

## 5. 不优先采用的效果及原因

这些是内容与交互适配判断，并不意味着正常模式需要降低表现力。

| 效果 | 当前不优先的原因 |
| --- | --- |
| GitHub Globe 整体替换 | 已有地球承担城市投影、点位避让、键盘、镜头恢复和拖动，替换会牵涉较多功能；可借鉴其空间层次 |
| Chromatic Image | 色彩分离、位移与倾斜更适合艺术海报；若用于建筑主图，可能干扰材质与细节判断，可作为独立实验 |
| Wobble／Draggable Card | 大幅摇晃或任意拖拽改变目录稳定性，也容易与点击进入作品竞争 |
| Focus Cards 全部照搬 | 模糊其他卡片会降低建筑标题和城市的可浏览性；可仅借鉴当前卡片突出 |
| Vortex／Cloud Shader 与地球同屏持续运行 | 多个运动主体竞争画面，并增加实时场景的渲染成本；若试验，应单独评估构图与帧时间 |
| 多种循环背景同时叠加 | 会削弱主光方向和页面视觉中心；建议每个区域确定一种主动态语言 |
| Compare／Timeline 直接增加到详情 | 目前没有匹配的成组图片或历史阶段数据，不能为了组件创造内容 |
| Multi Step Loader 播放固定进度 | 只有能对应真实预览状态时才采用，不用动画暗示尚未发生的加载成功 |

## 6. 工程可用性与适配成本

现有技术栈：React 19、Vite、TypeScript、CSS Modules、GSAP、Three.js／React Three Fiber。当前依赖未配置 Tailwind 或 Motion。

Aceternity 提供可复制的 React 源码，不要求本项目迁移 Next.js。Skill 中偏向 Next.js 的安装示例不是本项目的迁移要求。

建议首批以源码适配为主：将选中效果的样式转为 CSS Modules，继续用 GSAP 负责现有镜头和连续转场。若某个复杂组件完整移植 Motion 更合算，再局部引入，明确两者负责的 DOM 与属性。不要为获得几个视觉效果先改写全站样式体系。

公开 registry 源码核对结果：

- `spotlight-new` 使用 `motion/react`，并设置 `pointer-events-none`。迁入时仍需处理本项目的图层顺序、响应式尺寸及光向。
- `3d-card` 核心是 React 事件与 CSS transform，不依赖 Motion 来完成倾斜；样式、`cn` 工具和多层结构仍需适配。
- `glowing-effect` 使用 `motion/react` 的 `animate`，监听滚动与指针。若目录多卡片直接逐个照搬，应检查监听数量与失效清理；可限定为当前交互卡片的更新。
- `resizable-navbar` 使用 Motion 与 `@tabler/icons-react`。registry 的 dependencies 字段不足以替代 import 检查；原导航只有少量入口，可能只需借鉴材质和收拢运动。
- `text-generate-effect` 源码为 `words.split(" ")`，不能直接实现中文分段。中文按完整行或明确语义词组制作。
- `magnetic-button` 的官方默认 `maxDistance` 为 100px。项目应明显收窄漂移范围，初步可试 4–8px；点击命中区保持稳定。
- `liquid-glass` 官方说明折射仅支持 Chromium，Safari／Firefox 为磨砂玻璃，减少透明度偏好下为不透明。需把磨砂效果也设计完整，不能假定所有浏览器折射一致。
- Comet／3D 卡片的交互 transform 与现有 GSAP 入场应放在不同嵌套层，避免同时写同一元素的 transform。
- 卡片有倾斜时，进入详情的来源矩形要与临时代理一致；点击时的归正或代理交接需要验证，防止 Flip 起点跳变。
- Lens 仅用于封面图层。不要在真实 WebGL／视频观看区上复制第二层画面或截获模型输入。

源码核对入口示例：[3D Card registry](https://ui.aceternity.com/registry/3d-card.json)、[Glowing Effect registry](https://ui.aceternity.com/registry/glowing-effect.json)、[Text Generate registry](https://ui.aceternity.com/registry/text-generate-effect.json)。

## 7. 制作优先级与验证方式

| 阶段 | 具体交付 | 如何判断有效 |
| --- | --- | --- |
| 1：视觉样片 | 同一套真实封面制作首页、目录、详情静态稿；比较字体、标题尺度、材质和冷暖光 | 在不播放动画的情况下也有明确主次、作品辨识度和统一风格 |
| 2：代表交互 | 实现一个作品卡的 Comet／3D + 边缘光、一个主按钮、一个聚光开场 | hover、点击、键盘、触屏体验完整，效果之间不竞争 |
| 3：关键旅程 | 贯通“首页城市 → 作品 → 详情 → 开始预览 → 放大／恢复” | 转场连续、可中断；标题、画面和实际路由始终一致 |
| 4：推广与校准 | 推广到目录与详情，再校准导航玻璃和手机编排 | 390／768／1440 宽布局、长中文标题、返回恢复和减少动态均可用 |

性能验收用真实地球与代表模型一起测。60Hz 桌面争取接近 60fps，代表手机核心转场争取持续 30fps 以上；这些是沿用项目方向的目标，本轮未实测。大范围模糊、滤镜和多重实时画布单独检查帧时间。

## 8. 素材、费用与本轮边界

官网区分免费组件与 All-Access 中的页面区块和模板。本方案首先利用公开组件能力，不需要先购买整套模板。具体资源的付费状态与许可应以实际采用时的页面、文件为准。

[Aceternity Licence](https://ui.aceternity.com/licence) 中包含 Pro 资源的使用条款；已安装 Skill 文档的 MIT 声明不能当作组件、演示图片或全部 Pro 资源的统一许可。官网演示中的第三方照片也不自动成为项目素材。

本轮只新增本调研文档，未修改业务代码、旧版设计规范或安装前端依赖。后续视觉实现以本轮新方向为依据制定第二版规范，并用样片验证选型。
