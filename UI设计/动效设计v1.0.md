## 1. 动效主线

公开展示端采用空间镜头、分层时间轴和连续转场；地球、点位、封面及信息面板是动画主体。每个主要页面至少有一个能辨识的动态段落，首页和作品详情优先制作完整动态样片。动效与页面布局同时设计，不等全部功能完成后统一补入。

重点制作三组：

1. 地球、导航、点位按节奏进入，形成空间展厅的开场。
2. 明确选中城市后，镜头调整、城市点位确认、连接线与城市模型列表依次衔接。
3. 作品封面进入详情观看框，再展开标题与介绍，建立从浏览到观看的连续感。

保留正常模式的完整编排。系统“减少动态效果”仅为主动选择此偏好的用户提供替代呈现，不作为普通模式整体简化的理由。高级感通过节奏、构图和空间关系判断，不能只用动画数量或长时长验收。

## 2. 首期动效清单

| 场景 | 动态设计 | 建议时长 | 手机适配 |
| --- | --- | --- | --- |
| 首次进入首页 | 场景从略远镜位推进至最终构图；导航就位、地球光照层次显现、点位错峰出现 | 总长 1.2–1.6 秒，阶段重叠 | 保留镜头和错峰；减少位移幅度 |
| 再次回到首页 | 恢复浏览视角和原选中位置，短过渡收尾 | 250–450 ms | 保留，不重播开场 |
| 地球拖动 | 跟手旋转；松手短暂衰减，触摸／再次拖动立即接管 | 惯性尾段约 150–300 ms | 防止轻触被误判为甩动 |
| 电脑城市点位悬停 | 点位层次提升、连接线展开、城市气泡分层出现；模型列表可见项轻微错峰 | 气泡 280–380 ms，内部错峰约 40 ms | 手机通过点击触发；列表滚动不拖地球 |
| 明确选中点位 | 点击或键盘选择后，用最短合理路径将点位置于可见区域，再完成气泡展开 | 镜头 500–800 ms，与气泡重叠 | 同样保留，可被拖动中断 |
| 关闭／切换气泡 | 从当前状态收起或交叉替换，连接线同步回收 | 160–240 ms | 保留 |
| 作品目录出现 | 视口内卡片按行错峰揭示，封面遮罩与信息到位 | 单张 450–650 ms，错峰 50–80 ms | 保留，避免长队列 |
| 卡片交互 | 封面轻微推进、卡片上移、边界与阴影联动 | 180–260 ms；封面缩放约 1.025 | 点击反馈取代 hover；不依赖倾斜效果 |
| 封面进入详情 | 城市卡片或目录中被点击模型的封面框移动到详情观看框；标题、城市（可空）与介绍随后展开 | 封面 550–750 ms；信息段重叠 | 保留连续转场，移动距离随布局调整 |
| 直接访问详情 | 观看框、标题、信息按空间顺序展开 | 650–900 ms | 同样保留，不伪造来源卡片 |
| 开始预览 | 按钮反馈、观看区进入准备状态；真实首帧到达后封面与画面交接 | 开始反馈 150–220 ms；首帧交接 300–450 ms | 保持画面稳定 |
| 放大／恢复观看 | 同一观看实例平滑展开，介绍区退让，工具条同步就位 | 450–650 ms | 同样保留；退出路径持续可用 |
| AI 助手组件 | 完整组件负责入口／面板和内部动画；主站通过公开配置适配深色及位置，不另写内部时间轴 | 以组件实现为准，300–420 ms 仅为视觉对接建议 | 主站与组件共同检查软键盘、层级与观看操作避让 |
| 后台列表／表单 | 分区进入、保存反馈、状态标记更新 | 180–320 ms | 保留即时操作反馈 |

桌面 hover 仅打开可见点位的气泡，不自动带动整个地球，避免用户移向卡片时目标漂移。明确点击／键盘选中才触发镜头调整；气泡锚点跟随三维投影，边缘避让需与镜头同测。

首页开场的短暂镜头运动和拖动惯性纳入本版；持续自动旋转地球暂不启用，后续若要增加，应单独评审暂停与用户接管行为。

## 3. 首页开场分镜

以场景关键资源就绪为起点；网页导航应在资源等待期间可用。可先显示稳定背景或静态地球承托，不用黑屏遮住全站。

| 相对时间 | 编排 |
| --- | --- |
| 0–300 ms | 导航短距离到位，同时地球进入镜头 |
| 100–1100 ms | 镜头由约最终距离的 1.08–1.12 倍推进；地球短角度转向中国／东亚最终构图 |
| 550–1200 ms | 城市点位依次出现，使用城市中心位置；未设城市模型不产生点位，不添加虚构轨迹 |
| 900–1500 ms | 当前有真实选择时再展开对应气泡；无选择则停留在可探索场景 |

用户在任意时刻拖动或点击，立即取消剩余镜头动画，交出控制权；导航可随时离开。返回首页恢复位置，不强制重复完整开场。资源未就绪时不把动画播放完毕写成加载成功。

## 4. 转场、观看区与内容连续性

目录到详情首先验证单个封面元素的共享转场，只在来源与目标同一作品、图像及裁切可衔接时启用。其他内容使用重叠的分层入场；无有效来源、打开新标签或使用浏览器返回时均有独立路径。

转场克隆图只是视觉层，不保留重复的链接、焦点或可访问内容。导航提交与业务状态不依赖动画回调；资源较慢时照常显示目标页的真实加载状态。快速连续导航时终止旧动画，最终 URL、作品与画面一致。

封面到实时模型画面的切换只由真实首帧触发。封面与模型机位不一致时采用画面交接，不做假的模型变形。放大观看避免缩放 WebGL canvas 或 video 导致文字／画面拉伸，优先移动或缩放外壳的视觉代理，到位后更新真实容器尺寸；观看实例、远程会话、当前视角保持连续，输入坐标按当前显示区域计算。

正文在可读位置稳定后允许阅读；不逐字打散建筑介绍。短标题可按完整行揭示，文字放大与换行后仍保留完整语义。

## 5. 工程接入补充

现有 React + TypeScript + Vite、Three.js + React Three Fiber 主栈增加：

| 工具 | 职责 |
| --- | --- |
| GSAP + @gsap/react | 首页镜头与 DOM 多阶段时间轴、错峰、打断与卸载清理 |
| GSAP Flip | 选定封面转场及布局变化；先验证单个元素对 |
| CSS transition | 按钮颜色、边界、短反馈 |
| Three.js / Fiber | 实际相机、地球与模型场景渲染 |

具体版本安装时锁定。滚动触发需求出现时再使用 ScrollTrigger；不在纯地球首页添加无实际内容的滚动舞台，不强制全站平滑滚动或滚轮接管。

时间轴就近放在 globe、viewer 或页面中，共用缓动、时长层级放在 styles/motion 或同类小文件；首期不建通用动画调度平台。同一属性只能由一个系统负责：拖动接管前结束镜头补间，Fiber 渲染循环读取更新后的相机参数；不能让 GSAP 与控制器同时写同一相机值。

useGSAP 按组件作用域管理实例；交互后创建的动画也要纳入清理。取消转场、路由变化、窗口尺寸变化和卸载都要恢复正确的最终可见状态，移除临时遮罩／克隆图。逐帧变化使用引用或 Three.js 对象，避免逐帧 React 状态更新。

## 6. 质量、设备与替代呈现

正常模式：桌面与手机都交付首页开场、点位联动和详情连续转场。优先降低渲染分辨率、阴影和大面积模糊成本，保留核心编排。实际低性能设备仍持续卡顿时，可用更轻的画面交接，并记录触发条件和验收结果。

2026-10-18 用户确认流畅度优先：在核心复杂编排保留的基础上先优化资源与画面成本，按实际帧时间校准；首轮页面动画演示最晚 2026-10-25，可用明确占位图及 Mock 预览状态。AI 组件未交付隐藏入口，不为首轮演示自建聊天面板；微信内置浏览器不作为本期动画验收环境。

减少动态模式：取消大范围镜头推进、惯性与空间位移，保留清晰的状态结果及短交接。键盘焦点立即可见；手动拖动仍按用户输入响应。暂停在后台标签页中的装饰动画，返回后不补播积压时间轴。

首版目标：代表电脑动画接近显示刷新节奏，常见 60 Hz 设备以约 60 fps 为目标；约定代表手机核心转场争取持续 30 fps 以上。目标尚未实测，不作为已有性能结果。动画与真实地球／模型一起测，记录设备、分辨率、帧时间和是否出现明显停顿。

验收至少覆盖：反复进出首页、开场中拖动、快速切点、连续导航、详情刷新、观看中放大恢复、断线、手机横竖屏、软键盘、文字放大与减少动态偏好。操作无需等待一整段开场或转场结束。

## 7. 制作顺序与协作交付

1. 页面实现前：完成首页开场、点位联动、封面到详情的分镜与起终构图。
2. 地球／页面骨架阶段：用简单场景和现有封面制作三组可运行动态样片，确认节奏和中断方式。
3. 功能接入阶段：替换真实内容与状态触发，制作正常与失败路径；后台补完反馈，AI 助手挂载完整组件并验收其自带反馈和动画，不重复操控内部节点。
4. 联调阶段：在真实模型与手机上调整画面成本、时长、裁切和输入映射。

每项交付至少包含一段正常模式的运行预览、手机表现、可打断行为与待解决问题。静态截图不能证明动效已验收。只要前三组核心动画尚未制作，不能把公开展示端标为视觉交付完成。
